# QilbeeDB 0.14.0 release candidate

Status: **unreleased**. Feature batch #83–#87 is integrated; release metadata,
image qualification and deployment remain separate gates. This page does not announce that a running
installation has these capabilities. Read `/health` and `/openapi.json` from the
installation your application actually uses, and record its immutable image ID.

## Capabilities in this candidate

- Company agent display profiles provide human-readable names with revisioned
  updates and retained history. The application still owns agent identifiers.
- [Company learning discovery](../api/company-learning-catalog.md) and
  [evidence history](../api/learning-evidence-history.md) let administrators inspect
  authorized resources without manually entering resource IDs or issuing scoped
  credentials. Retained history does not establish current reuse eligibility.
- [Consumer diagnostics](../api/company-consumer-directory.md) expose scoped
  progress, pending events and incompatible history while preserving private
  subject boundaries and current administrative authorization.
- [External graph consolidation](../api/graph-consolidation.md) provides bounded,
  leased work, exact source references, publication fencing and explicit handling
  of unknown outcomes. The external worker owns inference; the database validates
  publication and retains its evidence.
- [Evidence-bound knowledge](../agent-memory/evidence-bound-knowledge.md) binds
  new procedural revisions to current memory evidence and external tool identity
  declarations. Qualification and current applicability remain distinct. Tool
  code, maintenance, publication and execution belong to the consuming application.

The knowledge endpoints use request/success contract version 2 under the existing
`/api/v1` prefix. Errors retain the platform version 1 envelope. Existing v1
procedures are not silently upgraded, and v1 selection cannot return v2 knowledge.
The database does not infer an executable implementation from a tool schema.

Existing cosine, lexical, hybrid and graph-assisted score meanings and opt-in
behavior remain unchanged. This release does not promote a retrieval method or
claim an improvement in agent reasoning. Embeddings remain externally supplied.

## Upgrade acceptance

Before deployment, qualify the exact image and its immutable source revision.
Preserve current production data and administrative authority; never use retained
customer records as disposable test fixtures.

1. Record the current image, version, document digest and rollback conditions.
   Validate an application-consistent backup and a stopped disposable copy before
   replacing the live process. Once new writes resume, restoring an old copy
   requires reconciling those writes.
2. Check existing company, account, credential, private subject, scope, memory,
   relation and checkpoint state. Compare identifiers, revisions and private
   payload fingerprints without placing payloads or secrets in public reports.
3. Confirm that the new image survives restart and that old clients preserve
   score semantics, scoped access and historical receipt interpretation.
4. In a declared synthetic scope, test the knowledge lifecycle, exact retry,
   current-source invalidation, company discovery, history pagination and revoked
   access. Synthetic qualification exercises mechanics, not cognitive efficacy.
5. Validate the human administration journey with the intended API image,
   including errors, recovery, keyboard interaction and narrow or enlarged views.
6. Coordinate the production maintenance window through the team collaboration
   protocol. Announce any shared local Docker replacement before it happens.
   Mark documentation as released only after the actual deployment is verified.

Do not downgrade a live database containing new knowledge or consolidation records
without an explicit compatibility assessment. Older code may ignore new records;
that is not proof that it safely preserves their meaning or lifecycle.

## Evidence and limits

The integrated source passed 773 workspace tests, with five existing auxiliary
fixtures ignored. An additional selector test then verified the shared boundary
of 4,096 distinct dependencies, cached reuse and rejection at 4,097 without a
partial winner. OpenAPI qualification covered 477 schema definitions and 92
embedded examples. These source results do not replace validation of the final
versioned image.

Procedural observations are time-bounded, not execution reservations. Selection
scans at most 1,000 procedure candidates and has no continuation cursor; an
incomplete candidate scan returns the baseline. External execution, cancellations
and business authorization remain application responsibilities. The recovery
fixture covers process termination without database destructors, not hardware
power loss. No formal accessibility conformance or state-of-the-art ranking claim
is made by this release candidate.
